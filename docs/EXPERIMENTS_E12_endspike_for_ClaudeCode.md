## 2. E12-A NO1 크롭 프레임 (출력 좌표 vs 센서·장면 좌표)

**아이디어.** NO1은 중앙 1:1 크롭이라 센서 한 열이 출력의 x − 2408 열로 간다. 스파이크가 센서·렌즈·장면에 붙어 있으면 NO1에서 **x ≈ 8265 − 2408 = 5857**에, 출력 이미지 좌표(JPEG·ISP 후처리의 열 위치)에 붙어 있으면 **x ≈ 8265**에 나온다. (장면과 센서는 이 단계에서 가를 수 없다. 카메라가 안 움직였기 때문이다. E12-B, E12-E에서 다룬다.)

1. NO1 본시험 10장의 윗엣지를 x = 1000\~9500(엣지가 보이는 범위, 사전 스캔 확인됨)에서 열마다 추적한다. 추적은 이전 열의 엣지 y ± 30px 안에서 교차를 찾는 방식으로 하고, 못 찾는 열은 NaN.
2. 같은 방법으로 줌 1.00 시편 5개(NO3·NO5·NO7·NO9·NO10, 각 5장)를 x = 6000\~11000에서 추적해 8265 스파이크가 재현되는지 먼저 확인한다(양성 대조).
3. 스파이크 정의(0절)로 NO1의 후보 위치를 찾는다. 좁은 창만 본다: 줌 1.00은 x = 8140\~8390, NO1은 5732\~5982와 8140\~8390. 열마다 엣지 y를 그 창에서 한 번 구한 대략 위치 ± 20px 안에서 찾는다(곡선·단차 구간의 오추적 방지).
4. "양성 대조 재현" = 줌 1.00 시편 5개 중 4개 이상에서 8265 ± 3에 스파이크.

**판정(고정).**
- 양성 대조에서 8265 ± 3에 스파이크가 재현되지 않으면 이 단계는 중단하고 보고한다(방법 문제).
- NO1 스파이크가 **5857 ± 3에만** 있다 → 센서·렌즈·장면 쪽(출력 좌표 고정 아님). JPEG/ISP 출력 단계 설명은 약해진다.
- **8265 ± 3에만** 있다 → 출력 좌표에 붙은 원인(JPEG/ISP 후처리 쪽).
- 둘 다 있거나 둘 다 없다 → 판단 불가. 이유를 적는다(NO1 엣지가 그 열에서 보이는지, 대비가 충분한지).

산출물: `results/E12A_no1_frame.csv`(열 x별 편차 중앙값, 줌 1.00과 1.41), `results/E12A_summary.csv`(후보 위치·깊이·판정), `figures/E12A_no1_frame.png`.

## 2-2. E12-A2 순위 검정으로 다시 보기 (E12-A가 "방법 문제, 중단"이라 새 단계로 재실행)

**왜 새 단계인가.** E12-A의 `strict` 판정은 양성 대조 3/5로 중단이었다(부록). 원인은 두 가지다. ① "창 전체에서 가장 깊은 한 곳"만 보므로 목표 밖에 더 깊은 홈이 있으면 목표의 유효한 홈도 미검출이 된다. ② −0.5px·2열 이상이라는 고정 임계값이 약한 스파이크(NO7, 14µm)를 가른다. 둘 다 규칙의 구조 문제이므로 규칙을 바꿔 새 단계로 다시 한다. **이 규칙은 E12-A 결과를 본 뒤 설계했다(사전 등록이 아니라 사후 설계).** 다만 E12-A2를 실행하기 전에 고정하고 커밋한다. 결과 의존적 조정을 막기 위해 아래를 실행 후 바꾸지 않는다.

**규칙(고정).**
1. 프로파일 `dev(x)`는 E12-A와 같다(열별 엣지 y의 장 방향 중앙값에서 ±6px 롤링 중앙값을 뺌).
2. 통계량 `s(x)` = `dev`의 3열 이동평균.
3. 목표 위치 `xc`(8265 또는 5857)에서 `t = min s(x), |x − xc| ≤ 3`.
4. 오프타겟 집합 = 같은 창에서 `|x − xc| > 8`이고 창 양끝 10열이 아닌 열. 순위 p = (1 + #{오프타겟 s ≤ t}) / (1 + 오프타겟 수).
5. **스파이크 있음 ⇔ p ≤ 0.05 이고 t < 0.** 인접 열은 상관이 있어 실효 독립 수가 줄어든다(보수적이지 않음). 이 한계를 결과에 적는다.
6. 양성 대조 = 줌 1.00 시편 5개(NO3·NO5·NO7·NO9·NO10)의 **본시험 사진 전체**(장수 많을수록 중앙값이 안정됨), 창 x = 8140\~8390. 5개 중 4개 이상에서 "있음"이면 재현. 아니면 "방법 문제, 중단".
7. NO1(본시험 10장 전체)은 5857 창과 8265 창 각각에 같은 검정. 판정 문구는 2절 그대로: 5857에만 있음 → 센서·렌즈·장면 쪽, 8265에만 있음 → 출력 좌표 쪽, 그 외 → 판단 불가. **"없음"은 "p > 0.05"일 뿐 부재의 증거가 아니다**(양성 대조에서 확인된 검출력 범위 안에서만 해석).

산출물: `results/E12A2_summary.csv`, `E12A2_profiles.csv`, `E12A2_verdict.csv`. 코드 `code/e12a2_rank_test.py`(공용 `e12_edges.py`, E12-A와 같은 엣지 추적).

## 3. E12-B 평평한 밝은 영역 열 프로파일

**아이디어.** 엣지와 무관한 영역에서도 x = 8265 열이 어긋나면 열 전체의 결함(센서 열, 렌즈 먼지, 역광판 얼룩, ISP 열 보정)이다. 평평한 곳에서는 멀쩡하고 엣지 근처에서만 튀면 샤프닝·압축·엣지 처리 쪽이다.

1. 본시험 110장(NO2\~NO12) 각각에서 윗엣지 위쪽 밝은 띠(y ∈ [center − 300, center − 80], 저장된 `top_center` 사용)의 **열별 평균 밝기**를 구한다. 이 띠가 포화(≥ 250)된 열이 있으면 보고한다.
2. 각 장에서 ±15px 롤링 중앙값을 뺀 뒤 장 방향 중앙값을 취한 열 패턴 `P(x)`를 만든다(x = 6000\~11000).
3. `P(x)`의 로버스트 척도 `MAD(P)`를 구하고, x = 8260\~8272의 `|P|`를 비교한다.
4. 같은 계산을 시편 안쪽(엣지 아래 어두운 영역)에는 하지 않는다(값 10 부근 클리핑이라 정보가 없다).

**판정(고정).**
- 8260\~8272에서 `|P|` ≥ 5·`MAD(P)`인 열이 있고 그 위치가 8265 ± 3 → 평평한 곳에서도 열 결함(센서·렌즈·장면·ISP 열 처리).
- 없음 → 엣지 근처에서만 생김(샤프닝·압축·엣지 처리 쪽).
- 5·MAD 기준 초과 열이 x 전체에서 흔하면(전체의 5% 초과) 기준이 의미 없으므로 판단 불가로 보고한다.

산출물: `results/E12B_flat_column.csv`, `results/E12B_summary.csv`, `figures/E12B_flat_column.png`.

## 4. E12-C JPEG 8×8 블록 경계 검사, E12-D 조명·세트 대조, E12-E 계획서

### E12-C

1. E12-B의 같은 밝은 띠에서 인접 열 밝기 차 `|I(x+1) − I(x)|`의 장 중앙값을 만들고, x mod 8의 8개 위상별 평균을 낸다(x = 6000\~11000). 같은 계산을 mod 16에도 한다.
2. **판정(고정):** 위상 7 → 0(블록 경계)의 평균이 8개 중 최대이고 다른 위상 평균의 중앙값의 1.1배 이상이면 "블록 흔적 있음". 아니면 "없음".
3. 스파이크의 위치를 x mod 8로 적는다(8265 mod 8 = 1, 8266 mod 8 = 2, 블록 경계는 8264). **스파이크가 블록 경계(위상 0 ± 1)에 있지 않으면 블록 경계 아티팩트라는 설명은 약해진다.** 반대로 경계에 있어도 우연일 수 있으므로 이것만으로 단정하지 않는다.
4. 산출물: `results/E12C_block_phase.csv`, `figures/E12C_block_phase.png`.

### E12-D

1. `3_암막없음` 사진(시편·장수는 폴더에서 확인해 보고)과 재장착 30장(NO7\~NO12)에서 윗엣지 스파이크를 같은 방법으로 찾는다.
2. 판정: 위치가 8265 ± 3으로 같으면 "조명·장착과 무관", 이동하면 "조명 또는 장착 의존"(이 경우 장면 쪽 원인 가능성). 암막 없음 세트에 엣지가 보이지 않으면 판단 불가로 보고한다.

## 6. 보고 형식 (단계마다)

1. 한 줄 결론(판정 문구는 위 고정 문구 그대로)
2. 방법 요약과 입력(사진 수, x 범위, 제외·NaN 수)
3. 표(핵심 수치) 1\~2개와 그림 경로
4. 사전 기준에서 벗어난 점·실행 중 결정(있으면)
5. 본 것 vs 못 본 것, 스테이징한 파일 목록
6. 다음 단계 제안은 한 줄만. 시작은 사용자가 지시할 때.

## 부록 — 실행 중 결정 / 사후 변경 기록

- 2026-10-27 (E12-A, Codex 리뷰 반영): 처음 실행 코드는 0절의 스파이크 정의(편차 ≤ −0.5px가 2열 이상 이어짐)와 달리 폭을 "최저점 주변 7열 중 −0.25px 이하 두 열"로 셌다. 코드를 지시서 문구대로 고쳐 세 기준을 나란히 `results/E12A_verdict.csv`에 낸다.
  - `asrun`: 실행 당시 코드(기록용). 양성 대조 4/5, 판정 "판단 불가".
  - `strict`: **사전 기준(지시서 문구 그대로).** 양성 대조 3/5(NO7이 단일 열 스파이크라 탈락) → 2절 규칙상 **"양성 대조 미재현 — 방법 문제, 중단"**. 이것이 E12-A의 공식 판정이다.
  - `target`: **사후 변경.** 창 전체 최저점 한 곳이 아니라 목표 x ± 3 안에 strict 구간이 있는지 본다(창 전체 최저점이 목표 밖의 더 깊은 홈이면 목표 위치의 유효한 홈도 미검출이 되기 때문). 양성 대조 4/5, NO1은 5857 ± 3에 있고 8265 ± 3에는 없음 → "센서·렌즈·장면 쪽". 단, NO1 5857 창에는 목표 밖 유효 구간이 4개 더 있어(250열 중) 목표 안 홈이 우연일 가능성이 작지 않다. 근거가 약하므로 결론으로 쓰지 않고 E12-B 이후의 방향 참고로만 쓴다.
- 이 지시서와 코드는 결과를 본 뒤에 커밋 이력에 들어갔으므로 "결과 전 고정"을 git 이력으로 입증할 수 없다. 이후 단계부터는 지시서·판정 기준을 결과 생성 전에 별도 커밋한다(사용자 지시 후).
- 실행 환경 버전은 `results/E12_env.txt`에 기록한다(`/usr/bin/python3`, matplotlib 필요).
- 알려진 한계: 집계 프로파일의 NaN(NO1 5857 창 5924\~5981, 엣지가 대략 위치 ±20px 창을 벗어남)은 목표 위치(5857)와 떨어져 있어 판정 직접 원인이 아님을 확인했다. 추적 방식은 바꾸지 않았다.
